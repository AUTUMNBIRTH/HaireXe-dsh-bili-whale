# 肥鱼硬邦邦 · dsh-bili-whale 个人修改版

> 基于 [Alterssss/dsh-bili-whale](https://github.com/Alterssss/dsh-bili-whale) 0.4.6 的个人修改版
> —— 在她原本"按作息自己看视频、写日记、@ 你"的基础上，加了聊天、主动和人格三个方向的东西。
> 原作者：[Alterssss](https://github.com/Alterssss)

原项目是「给 DSH 装一条有日子的鱼」：自己按作息醒来，刷 B 站、真看懂视频、写两本日记，
把值得的 @ 你。这一版改动不改变她的核心人格和日常流程，只是把**相处**的部分做得更像回事。

> **所有设计、架构、绝大部分代码都来自原作者 [Alterssss](https://github.com/Alterssss)。**
> 这个仓库只是我在自己使用过程中改的一版，不是官方版本，与原作者无隶属关系。

## 这一版多了什么

### 一、私信聊天：能像正常聊天那样回

**原来的问题**

她收到私信后只能把回复写成一个文件，插件读出来发**一条**。话一多就全挤在一条消息里，
读起来像一封信，不像聊天。

同时从你发消息到她回，中间卡着几道等待（轮询 60 秒 + 定时器 20 秒 + 写冷却 60 秒），
最坏要等两分钟以上。

**现在**

她说几句话就写几行，**一行 = 一条消息**，逐条发出去，中间停 1–3 秒，像人在打字。

```
刚看到你说的那个
我也觉得离谱😑
等会儿细说
```

→ 对方会收到 3 条独立消息，而不是一大段。

边界都处理了：空行忽略、`---` 当分隔、自动去掉包裹引号、写「（不回）」表示这次不说了、
超过 6 条截断。

**回复变快**

| 项 | 原值 | 现在 |
|---|---|---|
| 私信轮询间隔 | 60 秒 | 15 秒 |
| 私信定时器精度 | 20 秒 | 5 秒 |
| 私信写冷却 | 60 秒 | 2 秒 |

最坏首响从 2 分钟降到 **25 秒左右**。

> ⚠️ 这些是为手感调快的，**不建议当作默认值**。原项目 README 写过
> 「长时间高频轮询是小号被风控的头号原因」，那套保守默认值是对的。
> 号不老请调回去（见文末「风控提醒」）。

**修掉「她回好了却发不出去」**

实测发现：日记推送默认走私信，会和聊天抢同一份写额度。额度用满后，
她回复写好了、插件却发不出去，日志里是 `TrafficError: 已达到本地写操作预算`。

把日记推送改走本地文件（`notify.type = file`）之后，私信额度全留给聊天，这个问题没了。

这一条和上面的调参不同，**是真正的设计缺陷**。

### 二、主动与动态：她会自己找你了

**原来的问题**

她只会在「生物钟醒来」那一刻掷一次骰子，决定要不要主动找你。
一天醒 1–2 次，还要撞概率，实际表现就是：**永远是你找她，她从不主动。**

**三个触发时机**

| 时机 | 频率 |
|---|---|
| 生物钟醒来 | 1–2 次/天 |
| 聊完补话 | 每次对话后，她回完 30–90 秒再掷一次 |
| 久未联系 | 3 小时没说话后，每 10 分钟检查一次 |

默认概率 20%，日上限 3 次，**全部受作息窗口约束** —— 半夜三点不会突然来找人。

**醒来时发动态**

正常醒来时按 **30%** 概率掷一次，中了就让她发一条 B 站动态。日上限 1 条。

提示里明确约束：动态是**公开**的，关注者都看得见 → 不写只有你懂的私事；
短，1–3 行，像随手发的；不写成「今天看了什么」的汇报；**不要 @ 你**
（动态没这功能，会变死链）→ 想说话就走私信。

**她分享的评论下有人说话**

她 @ 你的那条分享评论下面如果有人说活，不该由她自己决定回不回 —— 那是公开评论区。

- 用 B 站收件箱的 `root_id` 匹配她历史分享评论的 `rpid`，精确识别
- 命中后私信问你：「要她回吗？回『回』或『1』，回『不回』或『2』」
- 你回「回」→ 坐标自动注入她那轮提示，她知道去哪条下面回复
- 她回复时用**对外的语气**（高冷、简短、不暴露跟你的关系），但按你的意思转述

### 三、人格设定：去掉规则腔

**原来的问题**

原 persona 里有一条写着：

> 面对成年角色之间的亲密话题，……同时遵守模型服务本身的限制。

这条本意是合规，但写在角色设定里，效果是**让她自己主动跳出角色做说明** ——
她会在聊天中间突然正经起来，念一句类似声明的话，然后才继续。

这正是「客服腔」的来源之一。

**改法**

把人设文件里**规则条款式的表述**换成**描述性格的表述**。核心人格全部保留：
傲娇、毒舌、腹黑、对陌生人高冷、对主人亲近、有主见会反驳。

删掉会触发「自我审查式发言」的写法，换成：

> 如果某个话题你确实不想往下走，用你自己的方式带过 ——
> 嫌他烦、岔开、骂他一句、或者说「今天不想说这个」。
> **不要**突然换成一个端正、客气、像在念说明书的腔调，那不像你。

新增一节「你不是什么」：不问「还有什么可以帮您」、不对自己的回复做总结、
不因话题严肃就换人格、不假装无条件赞同。

> 人格文件是用户自己的数据，放在 `~/.bili-ai/persona.md`，**不随仓库分发**。
> 这里只说明改法思路，按你自己的角色写就行。

### 顺带修的 bug

`tools/commands/dynamic.mjs` 启动时强校验 `sessdata` / `bili_jct` / `buvid3` 三项，
缺 `buvid3` 直接 `exit(3)`。

但私信和评论两条链路并不需要它 —— `msgfeed.mjs` 和 `dm.mjs` 只用
`SESSDATA` + `bili_jct` 就能正常工作。

结果：同一账号私信能发、评论能发、**动态发不出去**，而且报错指向
「凭据文件缺少 buvid3」，容易被误判成登录失效。

改为只强校验 `sessdata` / `bili_jct`；`buvid3` 有值时再拼进 Cookie。

### 四、两份说明文档

功能一多就不好记了：哪个开关管什么、改哪个文件、数据存在哪、出问题先看什么。

**[FUNCTIONAL-GUIDE.md](./FUNCTIONAL-GUIDE.md)** 是按本机实跑配置整理的说明书：

| 章节 | 内容 |
|---|---|
| 五个功能模块 | 作息时间窗 / 看视频命令链 / 两本日记 / 私信聊天 / 主动搭话 |
| 配置项全表 | 分享、监听、风控配额、身份、其他，全部标了当前值 |
| 数据文件在哪 | 哪些敏感（凭证、日记、人格），换机器该拷什么 |
| 风控与安全边界 | 私信单向锁定、互关校验、Web 端口信任栅栏 |
| 常用操作与排错 | 手动发私信、改设置、看配额、常见故障对照表 |

单独标出了一件容易被忽略的事：**`share.enabled` 是开的**，她可以主动把内容发到公开评论区（`minScore: 13`、每日 1 条）。私信不外溢，但公开分享是另一条链路。想完全不出现在公开场合，把它设成 `false` 即可，私信聊天不受影响。

**[persona.example.md](./persona.example.md)** 是一份可直接用的人格模板（傲娇 / 小恶魔 / 毒舌），后面附了六条改人格的经验。两条最容易踩的：

- **别写「你现在是 XXX 角色」** —— 会让她跳出角色念声明，反而更假。直接描述"你是谁"比命令"扮演谁"有效
- **人格不是 system prompt** —— 它拼进的是用户消息前缀（`lib/session-delivery.js`），所以不会覆盖 DSH 的 persona 锚点，装了别的提示词类插件也不会打架

文档里也写清了"成人向"内容的实际边界，分三层看：

1. 人格里写"可以自然表达暧昧"**有效** —— 它影响的是模型愿不愿意写
2. **上游 API 网关的关键词拦截**绕不过 —— 触发时直接断连或返回 400，提示词层面无解
3. **B 站平台的私信风控**管的是发送行为本身 —— 私信是风控最严的接口（判营销 / 骚扰）

一句话：**模型愿不愿意说，和内容发出去安不安全，是两件事。**

## 风控提醒

这一版为了手感把一批参数调激进了，**不适合作为默认值**：

| 项 | 原值 | 本版 |
|---|---|---|
| 轮询下限 | 15 秒 | 5 秒 |
| 私信轮询 | 60 秒 | 15 秒 |
| 私信冷却 | 60 秒 | 2 秒 |
| 写额度（时/日） | 30 / 80 | 80 / 200 |
| 读额度（时/日） | 600 / 3000 | 900 / 8000 |

实测代价：15 秒轮询满速约 **5760 次请求/天**，原来的读额度撑不住，
所以读额度也一起放宽了。**号不老请调回原值。**

## 实现要点（给想看代码的人）

**多条消息怎么拆**

`parseOutgoing()` 按换行切分，逐条清洗：

- 空行丢弃
- `---` / `***` 等 markdown 分隔线当分段符
- 包裹引号自动去掉（`「…」` / `"…"`）
- `（不回）` / `(不回)` / `不回` → 返回空数组，一条都不发
- CRLF 兼容
- 超过 `HARD_CAP`（6 条）截断，保留靠前的

发送时每条之间 `gapMs(i)` 停顿 1–3 秒（第一条不等）。

**为什么走"写文件 + 插件代发"**

她那个会话的权限是 `ask`，自己跑 `bili.mjs dm --go` 会弹审批框。
审批没人点 → 那一轮永久挂起 → 之后所有消息排队 → 看起来像"发私信没反应"。

所以改成：她只把内容写进工作区内的文件（`workspace-write` 免审批），
插件进程读取后代发。插件本身有完整权限，且仍在请求保护层之下。

**主动发消息的三个时机**

- 生物钟醒来：`tick()` 里掷，只在 `normalWake` 时（跳过"今晚不看""网络暂停"）
- 聊完补话：她回完消息后 `scheduleFollowup()` 延迟 30–90 秒再掷
- 久未联系：`startIdleWatch()` 每 10 分钟检查，超过 3 小时没聊才掷

三者共用 `PROACTIVE_LEDGER` 日账本，且都要过 `inWindow()` 作息判断
（支持跨午夜窗口）。

**分享评论怎么识别**

B 站 `x/msgfeed/reply` 的 `root_id` 指向被回复的根评论。
把她历史分享评论的 `rpid` 收集成集合，用它匹配新回复的 `root_id` 即可精确命中。

来源两条：`quota.json` 的 `log`（`comment.mjs` 记账时带 `rpid`），
或自维护的 `whale-shares.json`（兜底）。

命中后坐标存进 `whale-share-reply-pending.json`，
主人回"回"之后注入她那轮提示。

## 已知未完成

- 原项目的测试套件**没跑通**：本地环境沙箱拦截 `spawn`（EPERM），
  `node --test` 起不了子进程。所以这一版**没有回归测试**。
- 新模块的逻辑、概率、窗口判断都单独验证过（概率统计 1–2 万次、
  作息窗口 13 个时间点含跨午夜、分享回复 4 种情况），但没跑完整测试套件。
- `multi-msg` 的 6 条上限、`proactive` 的日上限都是按个人使用习惯定的，
  不是通用最优值。
